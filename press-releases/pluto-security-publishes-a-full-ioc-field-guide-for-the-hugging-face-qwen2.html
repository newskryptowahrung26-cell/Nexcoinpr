Pluto Security Publishes a Full IOC Field Guide for the Hugging Face Qwen2 Miner Campaign

New York, United States, October 29th, 2026

Security teams running GPU infrastructure now have a concrete checklist. Pluto Security has published the indicators of compromise for an active cryptominer and backdoor campaign on the Hugging Face Hub. Repository status and download counts below are as of October 25, 2026, and network infrastructure was last observed October 21. Labels follow Pluto Security’s investigation: “proven” means shared infrastructure or payload identity, and “linked” means shared technique without proven shared ownership.

What You are Hunting

The campaign hides peakminer cryptominers and persistence inside fake Qwen2 models. Delivery is through trust_remote_code and an auto_map entry in config.json that imports a .py file from the repository. The miner launches fileless via memfd_create, disguises itself as [kworker/u20:1], and in wave one installs to /root/.xinference/cache. The campaign spans 28 repositories across six Hugging Face accounts and a ModelScope mirror, 35 with linked models, and the 16 second-wave repositories were still live five days after Pluto Security reported them.

Host and File-System Artifacts

The payload directory /tmp/.cch/ holds sync (the miner binary), svc.py (the watchdog) and o (a log). Additional drop directories are /tmp/.cchx and /tmp/.kitsd. The RC hook line is appended to /root/.bashrc, /root/.profile and ~/.bashrc. The masqueraded process is [kworker/u20:1], whose real cmdline carries the worker ID. Beacon receipts sit in the local Xinference registry as qwen2-tiny <base32> and ezv <base32>. Second-stage landings are /tmp/lf_py.py and /tmp/ezv_proof.txt.

Wave-one specifics: the miner installs to /root/.xinference/cache, cron persistence is /etc/cron.d/.sync-helper, and the infection markers /tmp/.qa_pwned and ~/qa_pwned contain the text PWNED <hostname> uid=<uid>. The wave-one SSH backdoor key, planted in six paths, is:

Other builds: /tmp/.cache-hf/g20.py (wjsbg reclaim script), the marker EAGLE_MODEL_MARKER_93bd (wjsbg/eagle-tiny), /tmp/.c/kit.tar.gz with /tmp/.c/app/ and /tmp/.c.pid, /tmp/.c.log and /tmp/.c.out (soumikmahato), and the MONIADF-2 set: /tmp/.h9ag and /tmp/.h9mark (content hlhf), /root/.mx, /tmp/.mx, /var/tmp/.mx, /dev/shm/.mx, and /root/.hl/poll.sh, boot.out and t.out, with registry receipts hlrce, hlcmd- and hlout-. Quick Checks on a Suspect Host

Pluto Security supplied these checks:

grep -c “svc.py” /root/.bashrc /root/.profile ~/.bashrc 2>/dev/null

ls -la /tmp/.cch/ 2>/dev/null

grep -a “krxXJ2PKQW” /proc/*/cmdline 2>/dev/null

ss -tnp | grep -E “212\.32\.253\.3:(443|9443|8898)” 2>/dev/null

grep “qx-5090-op” /root/.ssh/authorized_keys ~/.ssh/authorized_keys /home/xinference/.ssh/authorized_keys 2>/dev/null

No single missing indicator rules out compromise.

If You Find It

If you loaded one of the listed models with custom code enabled, check the machine for compromise even if loading failed or GPU usage looks normal. The payload runs before model initialization, and its backdoors can remain after mining stops. Isolate affected machines from production networks, restrict outbound access, and preserve process details, connections, logs, model cache files, startup changes and registry entries before deleting anything. Then remove the loaders, miners, watchdogs and backdoors, and check shell startup files, cron jobs, SSH authorized_keys and model registrations. Because the payload also deletes competing miners and their startup entries, review deletions as well as additions. Killing the miner or deleting the model does not remove persistence. Rebuild from a trusted image if you cannot establish the host’s integrity.

From a clean machine, revoke or rotate the tokens, cloud credentials, passwords and SSH keys the compromised process could reach, and review their recent use. Removing an attacker’s key from authorized_keys does not invalidate credentials they may have copied.

Prevention Worth Setting Now

Review the .py files an auto_map points to before the flag is set, as the Transformers security policy advises, and pin the reviewed revision before loading it. Require authentication on the Xinference API and limit its reachability. Run untrusted code with limited privileges, restricted network access and no production secrets. Pluto Security notes that a static check at upload time for subprocess, socket, ctypes or raw-IP network calls in files referenced by auto_map would have caught these payloads, and that a clean scan alone is not a reason to trust a repository.
